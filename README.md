# پرتال خدمات شهری شهرداری

این پروژه یک رابط کاربری فارسی و راست‌به‌چپ برای پرتال خدمات شهری شهرداری است که با استفاده از React و Vite توسعه داده شده است. کاربران از طریق این سامانه می‌توانند خدمات مختلف شهری را مشاهده، ثبت و پیگیری کنند؛ از جمله مشاهده املاک، ثبت درخواست، پرداخت و استعلام عوارض، پیگیری پرونده‌ها و استفاده از پنل مدیریتی.

---

## امکانات سامانه

* مشاهده و مدیریت املاک
* ثبت و پیگیری درخواست‌های شهری
* استعلام عقب‌نشینی ملک
* مشاهده و پرداخت عوارض نوسازی
* مدیریت عوارض صنفی
* مشاهده اخبار و اطلاعیه‌ها
* پروفایل کاربری
* پنل مدیریت
* پشتیبانی کامل از زبان فارسی و چیدمان RTL
* ذخیره وضعیت ورود و تنظیمات کاربر در LocalStorage
* محافظت از مسیرهای حساس با ProtectedRoute

# نصب و اجرای پروژه

ابتدا وابستگی‌ها را نصب کنید:

```bash
npm install
```

اجرای پروژه در حالت توسعه:

```bash
npm run dev
```

پس از اجرا، پروژه معمولاً در آدرس زیر در دسترس خواهد بود:

```text
http://localhost:5173
```

ساخت نسخه Production:

```bash
npm run build
```

# اتصال به بک‌اند

صفحهٔ عمومی `/Receipt` اطلاعات قبض را از query string می‌خواند. در حالت
`Success=false` متن `Message` نمایش داده می‌شود و در حالت `Success=true`
فیلدهای `ParvandeNo`، `IdMalek`، `Year`، `ShenaseGhabz`، `ShenasePardakht`،
`CodeNosazi`، `NameOwner`، `Address`، `Description`، `DateSodor`، `Price`،
`DelayedPrice` و `PaymentStatus` نمایش داده می‌شوند. مبلغ‌ها بر حسب ریال هستند
و مبلغ کل از جمع `Price` و `DelayedPrice` محاسبه می‌شود.
قالب اعشاری مبلغ‌های صحیح ریالی که سرویس `Inquiry` می‌فرستد، مانند
`9700802.0000`، نیز پشتیبانی می‌شود؛ بخش اعشاری غیرصفر گرد یا حذف نمی‌شود.
اگر لینک دارای کد نوسازی کامل و شناسه مالک باشد، صفحه اطلاعات تازه را مستقیماً از
`/Api/PaymentAvarez/ReceiveBill?codeNosazi=...&ownerId=...` روی سرویس تنظیم‌شده با
`VITE_RENOVATION_BILL_API_BASE_URL` دریافت می‌کند. درخواست عمومی و بدون هدر ورود است.
قبض پاسخ باید با شناسه قبض، شناسه پرداخت و مشخصات پروندهٔ لینک مطابقت داشته باشد؛
پاسخ نامرتبط یا چندپهلو انتخاب نمی‌شود. فیلدهای ارسال‌نشدهٔ API از اطلاعات موجود
در لینک حفظ می‌شوند و مقدارهای صفر و وضعیت `false` نیز معتبر هستند.
هنگام دریافت اطلاعات تازه، پرداخت غیرفعال است؛ در صورت خطا، اطلاعات لینک همراه
با پیام خطا و دکمهٔ تلاش دوباره باقی می‌ماند. نام مالک و نشانیِ خالی «ثبت نشده»
نمایش داده می‌شوند؛ اگر این اطلاعات در هیچ پاسخی نباشند، فرانت‌اند آن‌ها را نمی‌سازد.

مطابق قرارداد فعلی عوارض نوسازی، `PaymentStatus=1` یا `true` به معنی پرداخت‌شده
و `0` یا `false` به معنی پرداخت‌نشده است. دکمهٔ پرداخت برای قبض پرداخت‌شده،
وضعیت نامشخص، شناسه نامعتبر یا مبلغ نامعتبر غیرفعال است. پرداخت قبض معتبر بدون
نیاز به ورود کاربر از سرویس موجود `/api/payment/token` و انتقال POST به درگاه
آسان‌پرداخت استفاده می‌کند؛ مبلغ موجود در لینک به سرویس پرداخت ارسال نمی‌شود.
درخواست پرداخت این صفحه بدون هدر `Authorization` ارسال می‌شود؛ endpoint دریافت
توکن در بک‌اند نیز باید پرداخت مهمان را بپذیرد. تنظیم فعلی SPA در
`public/web.config` از باز کردن مستقیم `/Receipt` روی IIS پشتیبانی می‌کند.

در محیط توسعه، تمامی درخواست‌های `/api` از طریق Vite به بک‌اند پراکسی می‌شوند.

تنظیمات مربوط به پراکسی در فایل زیر قرار دارد:

```ts
vite.config.ts
```

نمونه تنظیمات:

```ts
target: "http://192.168.10.3:6300"
```

در صورتی که بک‌اند روی آدرس دیگری اجرا می‌شود، کافی است مقدار `target` را تغییر دهید.

# نکات مهم

* پروژه برای نمایش کامل داده‌ها نیازمند اتصال به بک‌اند است.
* اطلاعاتی مانند توکن ورود، نوع کاربر و تنظیمات تم در `localStorage` ذخیره می‌شوند.
* مسیرهای خدماتی مهم توسط `ProtectedRoute` محافظت شده‌اند و قبل از دسترسی نیاز به ورود کاربر دارند.
* برای اضافه کردن صفحه جدید:

  1. فایل صفحه را در `src/app/pages` ایجاد کنید.
  2. مسیر مربوطه را در `src/app/App.tsx` ثبت کنید.

---

# توسعه و شخصی‌سازی

برای توسعه قابلیت‌های جدید می‌توانید:

* کامپوننت‌های جدید را در پوشه `components` اضافه کنید.
* صفحات جدید را در `pages` ایجاد کنید.
* APIهای جدید را از طریق Proxy یا سرویس‌های مجزا متصل کنید.
* تم و استایل پروژه را از طریق Tailwind و فایل‌های موجود در `styles` شخصی‌سازی کنید.
